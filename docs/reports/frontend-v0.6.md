# Frontend v0.6 — 장바구니·모의 주문

2026-11-08 KST. 장바구니, 주문서, 모의 결제 성공·실패, 주문 완료·내역·상세를 구현했다.

- 상품 상세에서 담기, 장바구니 수량 변경·삭제, 1~99 정수·판매 상태·재고 검증을 제공한다. 상품 30,000원 미만 배송비 3,000원, 이상 무료로 계산한다.
- 수령인·연락처·5자리 우편번호·주소·요청사항과 성공/실패 결과를 입력한다. 실제 PG·DB·배송지 조회 API를 호출하지 않는다.
- 성공 시 주문 당시 이름·가격·수량·배송 금액을 스냅샷으로 저장하고 해당 브라우저의 Mock 온라인 재고만 차감하며 장바구니를 비운다. 실패 주문은 별도 상태로 저장하고 재고·장바구니는 유지한다. 실제 DB 재고는 접근하지 않는다.
- checkoutToken으로 같은 요청 재처리 시 주문·재고 중복 변경을 막는다. 주문 내역은 현재 Mock 회원 또는 동일 브라우저 비회원 소유분으로 구분한다. 로그인하면 비회원 장바구니를 회원 장바구니로 병합한다.
- 상태는 `localStorage[daisomall.mock.v1]`에 남고 로그아웃·새로고침에도 회원별로 유지된다. 탭 로그인은 sessionStorage다. origin이 다르거나 초기화하면 공유하지 않는다. 서버 저장·동시성 보장은 없다.
- Tomcat 9 / Java 11 / Chrome 1440·1280·390px에서 담기 → 수량·합계 → 재고 초과 오류 → 실패 결제·재고 보존 → 재시도 성공·재고 차감·장바구니 비움 → 주문 내역·상세를 검증했다. 요청 재처리 멱등성, 30,000원 배송비 경계, 삭제·빈 장바구니, 이전 버전 및 공통 컴포넌트도 통과했다. 콘솔 오류·가로 넘침 없음.
- [실제 결과](frontend-commerce-evidence/v0.6-results.json), `v0.6-cart-*`, `v0.6-checkout-*`, `v0.6-payment-*` 캡처 참조.

로그인 시 비회원 장바구니 병합은 구현했으나 이 단계 자동 시나리오는 회원 주문을 중심으로 검증했다. 실물 모바일·다중 사용자 서버 격리·PG·보안은 미검증이며 실제 기능이 아니다. v0.7 관리자 화면으로 진행한다.
