# Frontend v0.7 — 관리자 Mock 화면

2026-11-08 KST. 고객 Header/Navigation/Footer와 시각적으로 구분한 청회색 관리자 레이아웃·사이드바를 구현했다. 기존 폰트·기본 CSS·Repository만 공유한다.

## 구현

- `admin/` 및 `admin/?view=dashboard|categories|products|inventory|stores|orders|users`. 고정 whitelist를 검사한 뒤 WEB-INF 관리자 JSP로 Forward한다.
- 대시보드: 상품·분류·주문·결제 금액 요약과 전체 Mock 초기화.
- 카테고리: 이름·노출·표시 순서 변경. 같은 부모의 순서 충돌은 교환한다. 원본 871개 ID·부모·단계는 고정이며 변경은 localStorage override다.
- 상품: 등록·수정·판매 상태·분류·가격·이미지·설명·온라인 재고. 신규 ID는 CUSTOM 접두사이며 관찰 표본의 이름·가격·분류 변경은 ADMIN_EDITED 출처로 구분한다.
- 재고: 온라인과 서울·부산·제주 체험 매장을 분리한다. 고객 상세에서 체험 매장 재고도 확인한다.
- 주문: 목록·상세, 허용 상태 전이, 취소 시 Mock 재고 복원. 원래 주문 가격 스냅샷은 상품 수정 후에도 유지한다.
- 사용자: 검색·활성/이용 중지·복원. 현재 관리자 본인은 상태 변경할 수 없다.
- 체험 관리자: `admin@example.test`, 임의 비밀번호 4자 이상. 로그인 페이지의 체험 관리자 버튼과 마이페이지 진입 링크를 제공한다. 클라이언트 권한 확인은 실제 인증·인가가 아니다.

## 실제 검증

Tomcat 9 / Java 11, Chrome headless 1440·1280·390px에서 고객 탭과 관리자 탭을 분리해 검사했다.

- 관리자 미로그인 안내 → 체험 관리자 로그인 → 대시보드 통과.
- 상품 수정 후 고객 이름·가격 반영, 판매 상태 변경 후 담기 비활성, 신규 등록 후 검색 노출 통과.
- 온라인 재고 9개·부산 매장 42개 저장 후 고객 상세 표시 통과.
- 카테고리 이름 변경·숨김으로 루트 메뉴 15→14개·복원 통과.
- 주문 PAID→PREPARING→CANCELLED 변경 후 고객 내역 반영, 취소 수량 복원, 수정 전 주문 단가 유지 통과. 결제 실패 주문의 PAID 변경 거부도 통과.
- 회원 이용 중지 후 고객 세션 비로그인 취급, 재활성화 후 복원 통과.
- 전체 초기화 후 기본 732개 상품·주문 없음으로 복귀 통과.
- 이전 버전 전체 주요 시나리오와 공통 메뉴 Hover/Tap/Keyboard/ESC/바깥 클릭·초점 복귀 통과. 정상 탐색 콘솔 오류·문서 가로 넘침 없음.
- 비회원 장바구니 로그인 병합, 비회원 주문, 회원별 주문 조회, 음수 담기 거부, 비관리자 변경 거부도 추가 검증했다.

[최종 결과](frontend-commerce-evidence/v0.7-results.json), 같은 폴더의 `v0.7-admin-dashboard-*`, `v0.7-admin-products-*`, `v0.7-admin-users-*`와 고객 캡처 참조.

초기 JSON 503 실패는 의도적으로 주입한 별도 오류 테스트다. 정상 탐색의 콘솔 오류 집계와 구분한다. 실제 복구 결과는 최종 결과 JSON과 요약에 기록한다.

## 한계

관리자 기능은 같은 origin의 브라우저 저장소만 변경한다. 다른 탭 고객 화면은 새로고침해야 한다. 실시간 동기화·서버 권한·감사 기록·동시성·DB CRUD는 없다. 모바일 표는 별도 영역에서 가로 스크롤하며 모든 열을 한 번에 축소해 보여주지 않는다. 실물 모바일·Safari/Firefox·스크린리더·Eclipse Publish는 미검증이다.

데이터 계약·초기화 조건·서버 교체 책임은 [Mock Repository 계약](../mock-repository-contract.md)에 기록했다. v0.7에서 종료하며 v0.8 수정은 진행하지 않는다.
